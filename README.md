# Дашборд ДТП

Веб-дашборд по дорожно-транспортным происшествиям автопарка: три экрана («Обзор», «Статистика по автоколонне», «Аналитика»), детализация до списка ДТП с выгрузкой CSV и векторный PDF-отчёт по каждому экрану. Данные берутся из API basgroup (`api-v2`) сразу по всем базам, к которым у пользователя есть право `Dashboard_Accidents`.

## Стек

React 19, TypeScript 6, MobX 7, React Router 7 (HashRouter), Recharts 3, jsPDF 4, Vite 8, Vitest. Архитектура — Feature-Sliced Design (`src/app`, `pages`, `widgets`, `features`, `entities`, `shared`).

## Запуск

Нужен Node.js 22+.

```bash
npm ci
cp .env.example .env.local   # при необходимости поменять адрес API
npm run dev
```

Вход — по телефону и паролю пользователя учётной системы. Ссылка доступа может содержать `?DB_GUID=…` — GUID базы передаётся при входе.

## Скрипты

| Команда                | Что делает                        |
| ---------------------- | --------------------------------- |
| `npm run dev`          | дев-сервер Vite                   |
| `npm run typecheck`    | проверка типов (`tsc -b`)         |
| `npm run lint`         | ESLint                            |
| `npm run format:check` | проверка форматирования Prettier  |
| `npm test`             | модульные тесты (Vitest)          |
| `npm run build`        | типы + продакшен-сборка в `dist/` |

CI (`.github/workflows/ci.yml`) гоняет typecheck → lint → format:check → test → build на каждый push и PR. Деплой на GitHub Pages (`deploy.yml`) запускается только после зелёного CI в `main`.

## Окружения

| Переменная          | Назначение | По умолчанию                                   |
| ------------------- | ---------- | ---------------------------------------------- |
| `VITE_API_BASE_URL` | адрес API  | `https://api-t3.basgroup.ru` (тестовый контур) |

Для продакшена адрес задаётся в `.env.production.local` или в переменных окружения CI.

## Как грузятся данные

1. `loginAppUser` (Basic, AppCode `ID_5817_DASHBOARD`) — список баз пользователя и `SESSIONID`.
2. `UserRight/Dashboard_Accidents` по каждой базе параллельно (не больше 5) — остаются базы с правом.
3. `Dashboard/DashboardAccidentStat` по каждой базе — постранично через `Offset`, строки проверяются на входе (`entities/accident/lib/parseRow.ts`), объединяются в один набор с `DB_INDEX`.

Отказ части баз не блокирует экран — об этом говорит баннер над контентом. Вся фильтрация по периоду и автоколоннам — на клиенте. Сессия живёт 10 часов и истекает после 30 минут без запросов.

## PDF-отчёт

Отчёт рисуется примитивами jsPDF по данным, а не снимком экрана (`src/features/pdf-report`). Шрифты Rubik встроены подмножеством в base64; чтобы пересобрать (например, добавить символы):

```bash
pip install fonttools
python scripts/build_pdf_fonts.py Rubik-Regular.ttf Rubik-Medium.ttf
```

## Открытые вопросы к заказчику

Правило категории «Без повреждения» и полный справочник `ACCIDENT_CAUSE_ID` (пока категория и KPI по ней скрыты), боевой контур API и хостинг, метод закрытия сессии на сервере, политика выгрузки персональных данных в CSV, нормировка сравнения автоколонн на размер парка.
